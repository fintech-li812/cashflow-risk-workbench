## 5. 财务口径：已经梳理到什么程度

详见 `交付\WB-FIN-001\WorkBuddy\v1\财务公式与口径总表.md`（25 条公式 F-01—F-25）。

**核心计算链**：

1. **M（月均刚性流出）** = 近 3 个完整月经营性流出均值（取 `现金流水!E`）
2. **S（月均刚性支出）** = 近 3 月（营业成本 + 管理费用）
3. **B（现金缓冲）** = 期末现金余额 + 已验证到账 − 刚性支出
4. **倍数** = B / M → 与行业 K 系数**严格小于**比较 → 静态灯（红/黄/绿）
5. **三层模型 FUSE(Q, D, P)** → 模型灯
6. 两灯**取严**（红 > 黄 > 不可判定 > 绿）

**关键结论**：

- 灯级比较是**严格小于**：1.4999 红、1.5000 黄、2.4999 黄、2.5000 绿（已独立复算）
- 57 条离线用例：**46 PASS / 0 FAIL / 11 BLOCKED**；11 项 BLOCKED 是规则没定所以**不判**，没有一项被算作通过
- **Python 脚本通过 ≠ 千问表格能跑**。所有"千问表格公式"**全部待平台验证**，这是审核报告明确写明的

**已登记的文档缺陷（D-01）**：v8 §4.3 的健康度报告样例**不能当验收基线**——它把 1.20、1.40 标成黄灯（按批准公式应为红灯），联合冲击写 −15 万（三项缺口合计 230 → 应为 −45 万），天数也与自身公式不符。

**14 项业务待确认（P-01—P-14）**，其中会**直接改变灯级结果**的几条：

- P-01「刚性支出」= 哪些科目、取哪一列、算几个月？（全库无定义）
- P-02 FUSE 剩余分支
- P-06 / P-07 K 系数来源（四行业 × 两位置全不一致）
- P-09「已验证到账是否已含在现金余额」——**答错就是重复计入、缓冲虚高、红灯变绿灯**
- P-10 Q 与 D 各有两种数法，而 0.3/0.5 阈值直接改灯
- P-14 授信 `筹资信息!C` 未区分已用/未用
