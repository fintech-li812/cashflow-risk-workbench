## 〇、先认清范围（一句话）

本期**只做制造业实际现金流**：看一家制造企业的每月经营现金流入、流出、净额、余额，并核对勾稽差异。**不做**服务业/科技/零售/建筑，不做信用评级、现金折扣、K灯级、Q/D/P/FUSE、压力测试、审批、定时推送。

## 二、已具备时怎么做（按场景）

### 场景 1：选企业 / 期间 / 版本
- 在平台选定企业（如恒驰精密制造）、期间（如 2026-08）、数据版本（source_revision）。
- 同一逻辑重试沿用**同一 request_id** 与相同 payload；新结果用新逻辑请求。

### 场景 2：确认数据单位与范围
- 看现金流水表头：A月份 / B月末日期 / C流水类型 / D经营性流入 / E经营性流出 / F净现金流 / G期末现金余额 / H说明 / I数据闸结果。
- 单位：**源声明万元**；规范单位元（CNY）。看到 D8=1631300 是**单位疑点**，不要当 16.31 亿或自行缩放，等 X/包A 确认。
- 范围：本表**仅经营现金**，不含投资/筹资；不要说"企业全部现金流已完整"。

### 场景 3：查公式结果
- 公式（平台重算时）：净现金流=流入−流出；期末=期初+净额；下一期期初=上期已核对期末。
- 当前样例 F/G 是**固定值非公式**，平台重算验收时需先重建公式（部署阶段动作，你不用做）。

### 场景 4：缺项追问
- 若看到缺期初余额、缺独立实际期末余额、缺投资/筹资分类 → 系统应提示具体缺项。
- **不要猜测、不要用 0 补齐、不要捏造完整结果**。缺独立余额时差异标"未提供/勾稽未完成"。

### 场景 5：改输入后重算
- 改某月流入后重算，应读取**重算后**结果，不复述旧缓存；若实际余额未改，差异会变化并展示。

### 场景 6：保存回执
- 保存一次结果后，系统返回回执（record_id、request_id、payload_sha256、status=committed）。
- ⏳ 待部署：真实原子提交完成后才有回执；**无 MCP 时不显示"已保存"**。

### 场景 7：同 request_id 精确回查
- 用 request_id + 企业/租户/期间/run 精确查同一条记录；**不能以"最新一条"代替精确回查**。
- 相同 (租户,企业,操作,request_id) 同 payload 返回同 record_id；不同 payload 必须冲突不覆盖。

### 场景 8：保存超时不确定
- 超时未确认时，按 request_id 重试（同内容）一次并检查无重复；优先查日志/连接。
- 仍不确定就标"⏳ 待确认"，不假称已入库。

## 三、看到什么算成功

- ✅ 读到了指定企业/期间的实际表格值与公式结果，并注明来源（Sheet/范围/快照）。
- ✅ 缺项被明确列出，而非用 0 补齐或隐藏。
- ✅ 差异≠0 时保留差异并给核查方向，未自动调平。
- ✅ 保存后有可信回执且能用 request_id 精确回查。
- ❌ 以下都不算成功：本地读取通过≠平台跑通；函数可用≠整链验收；经营部分≠完整现金流；样例带错被阻断≠真实数据通过。

## 五、问题提交流程

1. 记录：企业、期间、版本、你看到的输入与结果、截图（敏感信息打码，**不含密码/密钥**）。
2. 分级：P1=金额错误/重复计入/缺值产出完整结论/假称保存成功；P2=追溯或交互不完整；P3=不影响结果的文字布局。
3. 提交：统一交 X 检查，不分散发多个最终版本，不自行宣布项目整体验收通过。
