# 千问办公最终运行验收要求 v1
日期：2026-10-22（Asia/Shanghai）。来源：用户再次明确要求“必须在千问办公的环境下跑起来”。
这是项目交付的必要条件，适用于全部后续任务与审核；不取消已有串行、数据保留、权限与独立审核要求。

## 运行位置与分工
- 用户实际使用入口为千问办公中的Agent及工作台，不能以本地网页、Python demo或独立后端替代。
- 财务核心计算及Q/D/FUSE按批准架构在千问表格内运行，MCP提供批准的工具及RF推理，MySQL留痕。
- 平台能力必须实测；若实际平台不具备必要表格、公式、Agent读写或连接器能力，明确报告阻塞和可选方案，不悄悄把计算迁到外部并声称满足要求。

## 最终必须展示的真实流程
1. 在千问办公打开实际工作台/Agent，定位版本和测试数据。
2. 用户自然语言提出一次现金流风险分析请求。
3. Agent读取实际表格输入，使用批准公式得到可核对结果，不以提示词猜数。
4. Agent按批准权限调用真实MCP；业务记录写入真实MySQL，并返回可查询的标识。
5. 再查询记录，核对来源、版本、金额、时间和租户，与千问显示一致；解释风险原因及数据来源。
6. 至少验证一条失败路径：缺数据、未接通工具或数据库写入失败时，Agent如实说明，不报成功、不补零报绿。

## 证据边界
平台截图/链接或标识、表格公式与实际输出、脱敏工具调用与查询记录、MySQL核对证据共同支持端到端验收。
本地单测、靶机、离线HTML、Python计算及接口冒烟仅证明相应子模块，不代表平台接通。
当前尚未完成上述平台运行验收。自动提醒、定时任务与钉钉动作另按平台实测和权限验收，不预先宣称可用。
