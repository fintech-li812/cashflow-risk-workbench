## 三、三条最该先看的话

1. **Python 校验通过 ≠ 千问表格已能运行。** Q/D/FUSE 与全部财务计算的权威实现仍在千问表格，P 在 MCP（裁决一）。脚本只做离线算术复核，所有"千问表格公式"在总表里一律标注"待平台验证"。
2. **现金缓冲 B 有两个未决前提**：「刚性支出」全库没有定义（P-01），「已验证到账是否已含在现金余额」没有任何文件声明（P-09）。**后者一旦答错就是重复计入、缓冲虚高、红灯变绿灯**，属于最危险的一类错误。
3. **v8 §4.3 的健康度报告样例不能当验收基线**：它把 1.20 和 1.40 标成黄灯（但都小于 K红 1.5，应为红）、把联合冲击写成 −15 万（三项缺口合计 230，应为 −45 万）、天数也与自身公式不符（D-01）。演示看板审计行用的是 −0.45，与按批准公式复算一致。

## 四、单位、精度与舍入（一句话版）

- 表格与看板：**万元**，金额 ROUND 2 位；比值 ROUND 4 位；**判定用底层未舍入值**（包B E01—E06 行 266）。
- 库与 MCP 边界：**元**（DECIMAL(20,2)，裁决 D12），万元→元 ×10000 只在**接入层换算一次**，禁止整列换算（制造业 D8 已是元值）。
- 舍入模式统一 **ROUND_HALF_UP**（脚本初版一处漏写导致落回 ROUND_HALF_EVEN，1.865 得 1.86，已修正并在总表记录）。
