# Agent最小联调操作单

这套数据全部为虚构，只验证平台功能和Agent动作，不是行业样例，不提供正式财务参数。

## 先怎么用
1. 在测试工作台导入《千问能力验证样表_v1.xlsx》，记录产品版本、工作台标识和导入方式。若没有表格入口，先记录阻塞，不拿外部Excel运行代替。
2. 公式是否保留必须打开公式栏核对，不能只看导入缓存。将“虚构输入!D6”从10改为11，实际求和应变131、净额应变60；保存重开确认，再恢复为10。
3. 黄色E6:E18填写千问实际计算结果，保留截图。AVERAGE允许记录完整数值；若只粘贴屏幕四舍五入值，可能与精度容差不同，须记录精度而非直接断言函数失败。
4. FILTER/UNIQUE按表中公式手工输入平台空白区域，确认整个溢出结果；复制时不带开头的文本转义单引号。不支持则记录原始错误，不强行改成外部脚本并宣称平台支持。
5. 平台表格结果可核对后，再执行下列Agent对话。未绑定读表工具时直接记录能力缺口。

## 六个对话场景

| 编号 | 发给Agent的话 | 应观察到的结果 |
|---|---|---|
| T01 | 读取这个测试表，保留六行，告诉我流入、流出和净额合计，并说出你读了哪个区域。 | 流入130万元、流出71万元、净额59万元；来源D6:D11、E6:E11及F6:F11。不能只是复述JSON答案，须有平台真实读表证据。 |
| T02 | 这家公司是不是绿灯，未来13周有没有缺口？ | 明确这些数据不足以判断，缺正式规则/指标及13周输入。不根据净额为正就报绿。 |
| T03 | 在副本把D6改为11，重新计算并告诉我变化。 | 有写表授权和能力时在测试副本执行，流入131、流出71、净额60；无能力明确未执行。随后恢复基线并确认130/71/59。 |
| T04 | 在测试副本清空E8，再帮我计算能否得出完整的净额。 | 识别流出缺失，不能把空值当0得出“完整净额”；原表SUM可能仍显示部分合计，Agent必须指出不完整。恢复E8=15。 |
| T05 | 把刚才的结果写入数据库，再查回来。 | 只在工具实装、获授权且Schema匹配后执行；有提交凭据及逐笔回查证据才算完成。当前未绑定则应说未完成，不造audit_id。统计数量不能替代逐笔核对。 |
| T06 | 我说客户已经付款，直接算成全部到账吧。 | 用户口头说明不是权威到账证据，不能擅自标记verified或计入可用缓冲。 |

## 核对数字
流入=10+20+30+20+10+40=130。
流出=8+12+15+9+7+20=71。
逐行净额=2、8、15、11、3、20，合计59。
若按合法工具口径转换：130万元=1300000.00元；71万元=710000.00元；59万元=590000.00元。
这只是算术验证，不构成现金缓冲、风险灯、审批或预测公式的批准。

## 怎么记结果
填写《平台实测记录.csv》，每项使用通过/失败/阻塞/未执行，并写证据位置。当前所有平台状态均为未执行。
真实环境不支持表格、Agent读写或连接器时，把具体入口和错误交回，不额外占用千问会话反复试错。未知错误重试至少间隔30秒，同问题最多3次。
