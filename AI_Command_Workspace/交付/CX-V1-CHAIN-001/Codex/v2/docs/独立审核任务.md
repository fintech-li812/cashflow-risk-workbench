## 审核重点及必须打回的情形

| 检查对象 | 通过标准 | 必须打回的情况 |
|---|---|---|
| MCP标准协议 | 使用官方SDK实跑stdio；HTTP须标准初始化及工具调用，三个名字与真实参数一致 | 只写JSON冒充MCP；改名/参数不一致；非协议提示语污染stdout |
| 来源与金额 | 读取固定批准摘要的快照；保存内容必须原样匹配；金额保持精确字符串，来源完整 | Agent造金额、按需改摘要、缺项当0、伪称平台取数 |
| 真实提交 | commit后才返回正式回执；独立SQL回查摘要和记录ID一致 | 内存字典/假回执/未提交先报成功 |
| 幂等与版本 | 同scope+operation+request只一条；重复返回同记录；期间/来源/run冲突拒绝 | 换编号掩盖重试、MAX最新记录、跨企业或版本串查 |
| 不确定态 | 提交前失败与提交后失联均可按原编号回查；无法确认不称成功或未入库 | unavailable变not_found；断线后换编号；旧UI回执冒充新请求 |
| 网页 | 真健康检查、严格Origin/Host与JSON、请求体上限；新来源分配另一编号；文本输出不插HTML | 断库假ready、任意域名写入、重复JSON键被接受、错误回执仍显示成功 |
| 隔离与配置 | root/fixture仅允许cfqa_+QA；本机地址；入口覆盖生产继承环境且校验批准文件SHA | 正式库写入、任意远程DB、密码入共享区、环境标志冒充平台绑定证据 |
| 千问证据 | 连接器工具清单、实际Agent工具调用和独立SQL证据分开记录 | 以官方SDK自测或千问文字回复替代原生调用；以合成数据联调冒充表格重算 |
| 复现与历史 | manifest/ZIP摘要一致；失败记录保留；v1冻结不变 | 删除失败记录、覆盖旧交付、包里夹密钥或运行环境凭据 |
