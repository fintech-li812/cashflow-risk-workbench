# 数据链与口径

依次重新核验账户绑定、现金选择与外部审批摘要，随后检查现金包引用的scope_binding快照是否等于本次账户绑定结果。过时快照不复用。
输入完整性在使用前后核验，避免抵销计划通过后有人改变原始内转金额，导致单账户核对漂移而合并净额未变。

单账户：选择count_external_actual与eliminated_internal_transfer的主记录；批准重复/业务旁证/非现金均不加入。
合并：只选择selected_records；内转两端不加入，经营/投资/筹资分类必须明确。所有账户主来源完整且无该分类事件时，合成夹具该分类可为0，不能在真实业务缺分类时擅填0。
调用旧baseline-cashflow-arithmetic.v1，公式、金额及mfg-agent-result.v1闭集不变。仅将无用DB服务导入换为JSON适配，因本模块只做离线，不需要连接库或装PyMySQL。

产物reconciliation.json含每账户核对、account_binding、selection、normalized_fixture_input与嵌套cashflow_result，另逐项导出并给SHA清单。
每项数字可追到原记录ID和已批准登记摘要；余额凭证真实性和批准人权限仍不由本地hash自动证明。
只有全部独立余额齐全、范围与选择ready、来源快照同版本才计算；缺项无财务结果。非0差异列待核，不修改输入或余额。
