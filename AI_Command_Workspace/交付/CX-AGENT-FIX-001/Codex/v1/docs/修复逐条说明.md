# 七反例修复与额外边界

AG-P01：缓存按当前run及快照四字段检查，新run不读旧run的结果；同run同快照才复用。
AG-P02：全部守卫及快照/公式版本检查通过才入缓存；错误路径清缓存。缓存入出均深复制。
AG-P03：result.source的workbook_ref/sheet/range/snapshot_ref必须与本次实际读取快照相同；可选快照公式版本提示也必须一致。
AG-P04：超时回查committed后核五字段、request_id、完整payload摘要和回执格式；异参冲突。未知/连接失败回查不当NOT_FOUND，不自动重写。pending请求已有摘要也不可换内容覆盖。
AG-P05：公开保存边界及内存参考存储入口都核结果身份、金额、完整性；回执返回再次核内容。默认生产不接受fixture，显式测试Backend或关键字测试开关才允许。
AG-P06：build_save_payload仅返回内部ok（已存在的准备/读取状态），reason明确尚未提交；不再返回committed。这不是新增公共MCP状态。继承测试中仅该错误旧断言调整为ok，原文件保留。
AG-P07：读取只有显式ok且能力/载荷类型正确可继续；pending和未知状态、非success公式结果都阻断。

回归额外发现：原Fixture/返回值有嵌套可变别名，调用方改一次可能污染默认夹具或别实例；现构造、读取、绑定和Flow缓存边界深复制。显式空字典测试输入不再因or回退成默认成功。
保存超时按pending处理，回查连接中断仍未确认；不报已提交，也不据此重复提交。异常处理只接已知TimeoutError/ConnectionError，意外程序异常不伪装成业务BLOCKED。

限制：MemoryEvidenceStore仍为进程内参考，不是SQLite/MySQL；这里只验证故障语义，不证明持久化。参数准备仅做字段映射，不声称已做完整JSON Schema验证或真正工具调用。可信Binding本身不是认证实现；平台身份绑定及凭据管理未完成。
