## 第三节 · 项目红线（**必须让 GPT 遵守，违反会造成静默分裂**）

1. **不建业务表、不导入任何 DDL/数据**——建表脚本由指挥方统一发。当前存在两份互相冲突的表定义（队友 `audit_db` 版 vs 项目 `cf_workbench` 版），先建者胜会造成静默分裂。
2. **不 `GRANT ALL`、不给应用用 root、不建 host 为 `%` 的账号、不监听公网端口**。
3. **不放行 3306 / 8000 公网**（安全组只留 22 / 80 / 443）。访问一律走 SSH 隧道。
4. **已存在的同名库/表一律不 DROP**——要 `SHOW TABLES` / `SHOW CREATE TABLE` 贴回，由指挥方判断迁移。
5. **不"顺手优化"**未要求的配置，不改 OS 内核参数，不装未列出的软件；认为有必要就写进"待决定"等批复。
6. **如实报告**：没做的写"未做+原因"，失败的贴错误原文，**绝不为了看起来完成而改配置、跳步骤或美化输出**。
7. 重试纪律：间隔 ≥30 秒、同一问题最多 3 次；写操作只在幂等语义已确认时重试。
8. 口令/私钥**不回传明文**到对外报告；报告里只写"已存放于某路径"。

## 第四节 · 访问方式（隧道，唯一方式）

```bash
# 数据库（以 tun_admin 为例；tun_read/tun_app/tun_backup 同理替换账号与私钥）
ssh -N -L 13306:127.0.0.1:3306 -i tun_admin_key tun_admin@39.104.201.10
# 另开终端
mysql -h 127.0.0.1 -P 13306 -u cf_admin -p

# MCP（千问办公用，转发 8000；当前 MCP 尚未部署，8000 无监听）
ssh -N -L 18000:127.0.0.1:8000 -i tun_mcp_key tun_mcp@39.104.201.10
# 连接器填 http://127.0.0.1:18000/mcp
```

> 私钥权限必须是 600（`chmod 600`），否则 ssh 拒绝使用。
> 每个 `tun_*` 账号**只能转发其 permitopen 允许的端口**，越权会被服务器拒绝（这是设计内限制，不是故障）。
> 隧道不能手点：用 `autossh` + systemd user service 常驻（见 `cf-tunnel.service`）。

## 第八节 · 风险提示（给你本人看的）

- **root 私钥一旦交给云端 AI，就等于把服务器最高权限托付出去**。优先只给"数据库档"（`tun_admin` + `cf_admin`），它照样能建表、查询、改数据。
- 若给了 root 私钥，**用完请让我轮换**：作废旧公钥、重发新密钥、旧的从 `authorized_keys` 移除。
- ChatGPT 网页版 / Code Interpreter 沙箱**通常无法对外发起 SSH**（出网受限），它多半只能出命令由你本机执行；只有具备终端/工具能力的 Agent 环境才能真接管。交接前先确认这一点，别期待它"直接动手"。
- 团队成员各自持有自己的 `tun_*` 私钥，**不要混发**，也不要把 5 个私钥的整份文件（`cf_ssh_credentials.md`）发给 GPT——只给 `tun_admin` 那一段。
