## 一、访问方式：SSH 隧道，零暴露

### 1) 安全组（控制台动作，服务器侧无法修改，已说明边界）
- 我**无法从服务器修改阿里云安全组**（属云控制台/API，需你的 AccessKey）。以下为应在控制台执行的规则，**请你核对并设置**：
  - 入站**仅保留**：`22/SSH`（建议限定来源 IP，或保持密钥登录）、`80/HTTP`、`443/HTTPS`（网站已上线，nginx 已确认监听 0.0.0.0:80 与 :443）。
  - **不要新增** `3306` 与 `8000` 入站规则。
- **关键事实**：MySQL 只绑 `127.0.0.1`（见下佐证），公网 IP 的 3306 上**没有任何进程监听**，因此即便安全组误开 3306，外部也只会得到 "connection refused"——**绑定层已保证零暴露**，安全组是第二道防线。

### 5) 隧道常驻自愈方案
- 已交付独立文件 **`cf-tunnel.service`**（systemd user service，autossh 版，含纯 ssh 备选）。
- 该服务运行在**隧道发起方机器**（队友笔记本 / 应用机 / 备份机），**不是服务器**——因为隧道是把"本机端口"转发到"服务器 localhost"，发起方在客户端。
- **我无法在服务器上执行 `systemctl --user status`**（那是客户端机器）。以下是直接可用的文件内容与部署步骤，以及**预期** status 输出样例：

**`cf-tunnel.service` 内容（同交付文件）：**
```
[Unit]
Description=CashflowRiskWorkbench 常驻 SSH 隧道（DB 3306 + MCP 8000，自愈）
After=network-online.target
Wants=network-online.target
[Service]
Type=simple
Environment=AUTOSSH_PORT=0
Environment=AUTOSSH_GATETIME=30
ExecStart=/usr/bin/autossh -M 0 -N \
  -o ServerAliveInterval=30 -o ServerAliveCountMax=3 -o ExitOnForwardFailure=yes \
  -L 13306:127.0.0.1:3306 \
  -L 18000:127.0.0.1:8000 \
  -i %h/.ssh/cf_server_ed25519 \
  <sshuser>@39.104.201.10
Restart=always
RestartSec=10
[Install]
WantedBy=default.target
```

**客户端部署步骤：**
```bash
mkdir -p ~/.config/systemd/user && cp cf-tunnel.service ~/.config/systemd/user/
# 编辑 <sshuser> 与密钥路径（密钥须已对服务器授权）
systemctl --user daemon-reload
systemctl --user enable --now cf-tunnel.service
systemctl --user status cf-tunnel.service
loginctl enable-linger $USER      # 退出登录后仍常驻
```
> 前置：客户端需 `apt install autossh`（无 autossh 时用文件内纯 ssh 备选行）。**前置：服务器上必须有对应的 SSH 登录账号**（见第四节，当前服务器仅有 root 部署密钥，需为隧道使用者建受限 SSH 账号）。
