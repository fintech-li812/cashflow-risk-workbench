# 现金证据选择合同 v1

五字段沿用tenant_id/company_id/period/source_revision/run_id；输入四文件scope_binding.json/events.json/source_registry.json/decisions.json，外部trust不在bundle内。
trust.schema_version=mfg-cash-selection-trust.v1，industry=manufacturing、approval_ref、allow_fixture、approved_inputs四字节摘要，同五字段。程序不自动更新审批摘要。
scope_binding使用账户绑定模块mfg-account-balance-binding.v1，五字段在context内，scope_ready必须true；accounts为纳入账户，scope_summary.included_accounts数量匹配。外部批准范围不是认证。
其余三输入五字段在顶层，origin一致且为offline_fixture或operator_registered_evidence；scope.fixture须同来源类型。

events.schema_version=mfg-cash-event-records.v1。records每项record_id/source_id/source_record_key/account_id/kind/amount/unit/settlement_date/category/transaction_id/internal_transfer_hint。
kind现金cash_in/cash_out；非现金receivable_invoice/credit_limit/noncash_adjustment。现金必须同期间合法日期、已登记账户、CNY、非负两位小数字符串。非现金不计收付，不拿应收额比实际回款判错。
source_record_key保留导入行SHA；同一行可拆invoice与cash事实，所以按(key,kind)防重复，不私改共同源键算法。record_id本事件内唯一，主来源现金transaction_id明确，不按金额猜。

registry.schema_version=mfg-cash-source-registry.v1。sources每项source_id/role/account_ids/period，role是primary_actual/corroborating/noncash。
主来源每账户恰一个，complete和declared_zero显式布尔；无记录未声明真实0须阻塞。两个主来源不自动选优。corroborating仅作旁证，noncash源不能夹现金。

decisions.schema_version=mfg-cash-link-decisions.v1：
- duplicates：keep_record_id/duplicate_record_ids/evidence_ref。只有账户、交易ID、方向、日期、币种、金额及分类完全一致且审批明确才不重复计数；原记录保留轨迹。
- links：primary_record_id/corroborating_record_ids/link_type/evidence_ref。transaction_evidence要求同一实际现金事实；document_reference关联发票，不要求开票额等于本笔实际回款，支持正常分次回款。
- transfers：pair_id/out_record_id/in_record_id/evidence_ref。两端主来源、不同纳入账户、同日同币同金额且out/in方向，均满足才抵销；一笔不能复用。声明内部转账但未批准匹配则阻塞。

输出schema=mfg-cash-evidence-selection.v1，status为本地计划ready/blocked/invalid，不是业务status或gate词表；selected_records、每条record_decisions和批准转账轨迹。计数闭合，cashflow_totals始终null。
暂未完成真实文件导入与原生取数，本模块只验证操作者提供的登记；source_authenticity_verified/native_sheet_verified/can_save_source_result/can_claim_full_cashflow均false。
