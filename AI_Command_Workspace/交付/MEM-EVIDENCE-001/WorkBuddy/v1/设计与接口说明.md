# 设计与接口说明（MEM-EVIDENCE-001 候选 v1）

## 1. 存储结构（本地 SQLite，schema_migrations 版本=1）

```sql
evidence_records(                       -- 正式结果快照（仅 success 且校验合格）
  record_id TEXT PRIMARY KEY,           -- 本地存储ID，非MySQL主键
  tenant_id TEXT NOT NULL, company_id TEXT NOT NULL,
  operation TEXT NOT NULL,              -- 固定 save_cashflow_result
  request_id TEXT NOT NULL,
  period TEXT NOT NULL, source_revision TEXT NOT NULL, run_id TEXT NOT NULL,
  status TEXT NOT NULL,                 -- committed
  payload_sha256 TEXT NOT NULL,         -- 规范JSON的SHA256
  payload_json TEXT NOT NULL,           -- 规范JSON原文
  stored_at TEXT NOT NULL,              -- UTC ISO8601 毫秒
  fixture INTEGER NOT NULL DEFAULT 0,
  UNIQUE (tenant_id, company_id, operation, request_id)   -- 幂等唯一键
)
diagnostics(                            -- 非 success 诊断记录，不产生回执
  diag_id TEXT PRIMARY KEY, ... 同上身份字段 ...,
  result_status TEXT NOT NULL, issues_json TEXT NOT NULL,
  payload_sha256 TEXT NOT NULL, payload_json TEXT NOT NULL,
  stored_at TEXT NOT NULL, fixture INTEGER NOT NULL DEFAULT 0,
  UNIQUE (tenant_id, company_id, operation, request_id)
)
```

迁移策略：`schema_migrations` 记录版本号；新库自动应用 version 1 DDL（`CREATE TABLE IF NOT EXISTS`）。后续结构变更升版本号并追加迁移语句，不改旧版本语句。

## 2. 事务边界与回执时序

```
校验(不落库) → BEGIN IMMEDIATE → SELECT 同键
   ├─ 已存在且摘要相同 → ROLLBACK → 返回原回执（幂等回放，不写）
   ├─ 已存在且摘要不同 → ROLLBACK → conflict，旧记录不覆盖
   └─ 不存在 → INSERT → COMMIT → 【只有此处之后】生成 committed 回执
```

- 回执只在 COMMIT 成功后产生；COMMIT 前任何异常 → ROLLBACK，不留半条（TC-15 实测）。
- COMMIT 后、回执返回前进程崩溃（故障注入 after_commit，子进程 exit 42）：重试同 request_id 先查库，命中回放原 record_id，不写第二条（TC-16 实测）。
- 锁等待：PRAGMA busy_timeout=5000 一次性承担；超时明确返回 store_error(exit 5)，应用层不无限重试。
- 并发同键竞争：UNIQUE 约束兜底；IntegrityError 后重查，按回放/冲突判定。两子进程并发实测：同参 [0,0] 行数 1；异参 [0,2] 行数 1（TC-17）。

## 3. 幂等与确定性 ID

- 唯一键：`(tenant_id, company_id, operation, request_id)`。
- `record_id = "ev-" + SHA256(tenant|company|operation|request_id|payload_sha256)[:24]`，确定性派生：同键同摘要必得同 ID；verify-store 可重算该关联以检出身份/摘要篡改。
- payload_sha256 对完整结果对象的规范 JSON（`json.dumps(..., ensure_ascii=False, sort_keys=True, separators=(',',':'), allow_nan=False)` UTF-8）计算，不含回执本身。

## 4. 当前有效选择规则（history）

限定 `(tenant_id, company_id, period)` 后按 `stored_at` 升序（并列按 record_id 字典序）排列，**最后一条为当前有效**；选择规则随响应明示。绝不以 `MAX(record_id)` 跨主体取"最新"。历史只追加：source_revision/run 变化产生新记录，旧记录保留且不改写。

## 5. 防混查

- `get` 必须同时给 tenant_id + company_id + record_id；记录不存在与属于其他身份**统一返回 not_found**，不区分，避免泄露别家记录存在性。
- `history` 只接受 tenant_id + company_id + period 三重限定。
- CLI 自填 tenant/company **不是认证**——见 trust_boundary.md。

## 6. fixture 隔离

- `origin=offline_fixture` 默认拒绝（exit 4）；显式 `--allow-fixture` 才接受，且回执/get 输出带 `fixture_marker: 【合成离线夹具，非平台真实结果】`，库内 `fixture=1` 持久标记。
- `origin=qwen_sheet` 仅表示格式合规；**origin 标签本身不是平台证据**（结果边界接口第 7 条）。fixtures/result_qwen_labeled_fixture.json 全为合成数据，仅验证代码路径。

## 7. 与 Agent 包（WB-AGENT-003 参考候选）的候选适配说明

- 校验口径继承 `agent_guard.py`（金额格式/勾稽/状态闭集/fixture 约束），本包补持久化。
- `MemoryEvidenceStore`（进程内字典）的语义在本包由 SQLite 落地；`persistence.py` 的 `retry_after_timeout` 约定（超时后必须沿用同一 request_id 先回查）与本包幂等回放一致：同键同参返回原 record_id。
- 替换方式：WB-AGENT-003 合并时把 `MemoryEvidenceStore` 换成对本 CLI/库的真实调用即可，RequestFlow 与守卫链路不需改动（参考候选 Agent接口映射.md 第三节的适配缝）。
- FIELD_MAPPING 的真实工具 inputSchema 本包未取得，不预设平台字段名。

## 8. 故障注入入口（仅测试）

`save --fault-inject before_commit|after_commit`（默认 none）：
- before_commit：INSERT 后 ROLLBACK 并抛 FaultInjected → exit 5，库中无半条。
- after_commit：COMMIT 后 `os._exit(42)` 模拟回执未返回进程崩溃（只能在受控子进程使用，测试 runner 以 subprocess 调用）。

## 9. 路径与 SQL 安全

- `--store` 解析后必须位于 `--workdir` 内（未给 workdir 时以 store 所在目录为界）；越界拒绝（exit 4）且不创建目标文件（TC-23/23b 实测）。
- 拒绝覆盖非空且非 SQLite 头的既有文件。
- 全部 SQL 参数化；request_id 含 `'); DROP TABLE...` 实测安全落库可回查（TC-24）。
- 不接受任意 SQL 语句入口；无"执行用户 SQL"功能。

## 10. 脱敏

错误消息只含字段名/规则名/record_id/退出码，不含金额流水、payload 原文、凭据或绝对路径细节；stderr 仅打印异常类型名。
