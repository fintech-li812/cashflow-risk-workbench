# 给WorkBuddy的合入步骤（排队，未授权并行开工）

本轮只补离线调用前校验；没有替代WB-AGENT-003、没有安装平台MCP、没有真实保存。须先由DeepSeek独审，然后Codex排串行合入任务，X检查结果。

## 必须插入的位置
在candidate/persistence.py的build_save_payload返回ok之后、任何实际MCP传输之前，调用tool_call_guard.prepare。旧函数只组装字段，ok不是提交证明。不要把此函数重命名成真实MCP工具，不得新增虚构接口。

1. 平台绑定层从认证会话取得五字段和稳定request_id；不从表格或待提交参数反推。
2. 先跑Agent公共结果校验、显式fixture许可、来源定位比对，再构造参数。
3. 从当前平台的真实tools/list取得唯一精确匹配的工具描述符。无权限、无描述符、同名重复、描述符变更未复核，都返回现有unavailable，不选择“相似名称”。历史14工具候选仅能做兼容检查。
4. 人工审定字段映射，写明五字段及request_id在参数中的JSON Pointer。某真实工具无法携带完整上下文时，先报合同缺项，不把上下文硬塞进未批准字段，更不能省略隔离条件。
5. prepare返回blocked：适配器映射为现有unavailable，保留无敏感值的reason；绝不调用传输。
6. prepare返回prepared：只取返回深复制的call用于后续传输，校验后不再改写参数。descriptor_sha256和call_sha256仅是本地指纹，不证明平台来源与持久化。
7. 传输超时/断连继续沿现有pending语义处理；回查同完整上下文、request_id、payload hash，再接受真实receipt。prepared不进入Agent业务状态闭集，也不产生committed。

本包CLI不负责执行步骤1/2/3/7；Python API不提供认证或网络。所有额外平台能力仍未就绪。

## 合入验收必须补的现场证据
真实且已授权工具目录的脱敏快照、权限范围与精确工具名；描述符哈希；可信五字段与请求编号的来源；人工批准映射；批准公式结果与快照；真正发出的参数指纹；正常/非法参数各一条现场轨迹；传输超时后准确回查；MySQL独立查询记录与receipt比对。不得把本包fixtures或“14个schema可解析”写成平台验收通过。

本期仅制造业实际现金流；旧目录含评级、预测、审批、推送等暂停能力，兼容检查不启用它们。event_type、occurred_at、source_ref如何从制造业结果取得仍需实际工具合同批准，不能为了过schema随便编。
