# MEM-EVIDENCE-001 设计与接口说明

任务编号：MEM-EVIDENCE-001（原总清单 D03/D04，接原任务二）。作者：WorkBuddy（AI）。版本：v1。
范围：制造业现金流结果的**本地可靠存储、幂等保存、精确回查与故障恢复**。不实现主算法、不连生产库、不部署。

---

## 1. 要解决的三个问题

1. **真的提交了没有** —— 只有 SQLite 事务 `COMMIT` 成功返回之后才生成回执；提交前崩溃不留半条（TC-13）；
   提交后回执丢失，先精确回查再同 ID 重试，返回原 record_id（TC-14）。
2. **重试会不会写两遍** —— 幂等唯一键 `(tenant_id, company_id, operation, request_id)` 建唯一约束，
   用 `BEGIN IMMEDIATE` 串行化；同键同摘要回放（TC-02），同键异摘要冲突且不覆盖（TC-03），
   6 进程竞争仍只有一条记录（TC-15）。
3. **查回的是不是同一版本和企业** —— 读时复核 payload 摘要与身份关联（TC-19/20/21/22）；
   历史只追加并给出可解释的当前版本选择规则，绝不跨企业取 MAX(id)（TC-17）。

## 2. 存储结构与迁移

SQLite（journal_mode=DELETE，synchronous=FULL，busy_timeout=3000ms）。

**schema_meta**：`key/value`，记录 `store_schema_version=evidence-schema-1`。

**evidence_record**（正式结果，只追加）：

| 字段 | 说明 |
|---|---|
| id | 自增主键，仅用于库内排序 |
| record_id | `loc-` + SHA256(tenant\|company\|operation\|request_id\|payload_sha256) 前 24 位，确定性 |
| tenant_id / company_id / period / source_revision / run_id | 五个共同身份/版本字段 |
| operation | 固定 `save_cashflow_result` |
| request_id | 逻辑请求 ID（重试沿用） |
| status | 仅 `committed` |
| origin / is_fixture | 来源标签与合成夹具标记 |
| reconciliation_state | 本地元数据：completed / not_performed / difference_pending_review |
| payload_sha256 | 完整结果对象的规范 JSON SHA256 |
| payload_json | 结果对象（规范序列化） |
| stored_at | UTC，`YYYY-MM-DDTHH:MM:SSZ` |

唯一约束：`UNIQUE(tenant_id, company_id, operation, request_id)`；索引 `(tenant,company,period,source_revision,run_id)`。

**diagnostic_record**（非 success 诊断，只追加）：身份字段 + request_id + result_status + reason + 摘要 + 原文。
诊断记录**不生成** mfg-evidence.v1 回执。

**append-only 触发器**：`trg_evidence_no_update / trg_evidence_no_delete / trg_diag_no_update`，
对 UPDATE/DELETE 直接 `RAISE(ABORT)`。篡改检测用例会先移除触发器以模拟具备库文件写权限者（见 tests/tamper_db.py）。

**迁移**：空库建 v1；识别到非 `evidence-schema-1` 的版本直接报错，不静默升级。DDL 见 `src/evidence_store.py: DDL_V1`。

## 3. 规范 JSON 与摘要

```
payload_sha256 = SHA256( json.dumps(obj, ensure_ascii=False, sort_keys=True,
                                    separators=(",", ":"), allow_nan=False).encode("utf-8") )
```
- 摘要针对**完整结果对象**，不含后来生成的回执。
- 金额一律为元、2 位小数的十进制字符串；`NaN/Infinity` 在解析阶段即被拒绝（退出码 3）。
- 缺独立实际余额时 `actual_closing` 与 `difference` 同时为 null，本地标记 `not_performed`，
  **不伪造差异 0**；差异不为 0 时标记 `difference_pending_review`。

## 4. 事务时序

```
save: 解析(禁非有限值) → 校验(五字段/状态/金额勾稽/origin) → 计算摘要
      → BEGIN IMMEDIATE
          → SELECT 同幂等键
              · 存在且摘要相同 → COMMIT → 返回原回执(replay)
              · 存在且摘要不同 → ROLLBACK → CONFLICT(4)
              · 不存在         → INSERT → COMMIT
      → COMMIT 成功之后才构造 mfg-evidence.v1 回执
故障注入点：
  --fault-before-commit : INSERT 之后、COMMIT 之前 os._exit(9)（崩溃，重启后自动回滚，0 条）
  --fault-after-commit  : COMMIT 之后、回执返回前 os._exit(9)（库中有 1 条，调用方无回执）
  --simulate-unknown    : COMMIT 之后回执未确定交付 → UNKNOWN_STATE(11)，不得报成功
锁：busy_timeout=3000ms 到点仍拿不到写锁 → STORAGE_BUSY(7)，不重试循环。
```

## 5. 幂等与冲突

| 场景 | 行为 | 退出码 |
|---|---|---|
| 同身份 + 同 operation + 同 request_id + 同摘要 | 回放原 record_id，不新增记录 | 0 |
| 同键不同摘要 | 冲突，拒绝覆盖，返回已有 record_id 与双方摘要前 12 位 | 4 |
| 摘要相同但 tenant/company 不同 | 视为不同主体，互不干扰 | 0（各自独立记录） |
| source_revision / run_id / period 变化 | 不复用旧记录，必须新逻辑请求 ID；旧记录保留 | — |

## 6. 历史与当前有效记录

- `history --period YYYY-MM [--source-revision X]` 只返回**同 tenant + 同 company + 同 period**的记录。
- 排序 `(stored_at, id)` 升序，最后一条标记 `is_current`，并在响应里返回 `current_selection_rule` 原文说明。
- 存在多个 `source_revision` 时返回 `ambiguous_versions=true` 与版本清单，要求调用方显式指定版本；
  旧版本既不删除也不被改写成新源结果（TC-17）。
- 跨企业/跨租户的"取最大 ID 当最新"是明确禁止行为，代码中不存在该路径。

## 7. verify-store 检查项

1. `payload_json` 规范摘要 == `payload_sha256`（篡改业务值 → PAYLOAD_HASH_MISMATCH）
2. payload 五字段 == 记录列（篡改关联身份 → IDENTITY_LINK_BROKEN）
3. 回执关键字段非空且 `status=committed`（缺失 → RECEIPT_INCOMPLETE）
4. 金额勾稽仍成立（被改坏 → AMOUNT_RECONCILE_FAILED）
5. 诊断记录不得自称 committed（→ DIAGNOSTIC_MISLABELED）
检出任一项即退出码 8。**普通哈希不能抵御能重写整个库及全部可信摘要的攻击者**，本包不宣称不可篡改审计。

## 8. 安全与边界

- 库文件只能建在 `--workdir` 内：路径 `realpath` + `commonpath` 校验，拒绝 `..` 穿越、绝对路径越界、非 `.sqlite3` 后缀（退出码 2）。
- 全部 SQL 参数化；不接收任何外部 SQL；SQL 特殊字符身份可正常存取（TC-24）。
- 自填身份必须与可信上下文一致，否则 SCOPE_DENIED（退出码 6）；越权响应不含记录内容。
- 默认拒绝 `origin=offline_fixture`；`--allow-fixture` 下输出醒目标识【合成数据·非生产·offline_fixture】并在回执标记 `is_fixture`。
- 输出脱敏：只含 record_id、摘要前 12 位、身份 ID、状态与字段名；history 默认不带金额。
- 静态边界检查无外连、无删除逻辑、无凭据读取（TC-27）。

## 9. 与 Agent 候选（WB-AGENT-003）的适配说明

| 参考候选 | 本包做法 | 差异原因 |
|---|---|---|
| `MemoryEvidenceStore`（进程内字典，不持久、不跨进程） | 替换为本地 SQLite 事务存储 | 任务书明确要求"不能照搬"，必须落盘、重启可读回 |
| `record_id` 前缀 `local-` | 改为 `loc-` + 确定性摘要 | 便于回查比对与冻结独立预期；待裁决（见 未实现与待确认.md） |
| `build_save_payload(input_schema)` 未取得 schema 即 unavailable | 本包不对接平台 schema，直接持久化本地 | 本任务边界是本地存储；平台 schema 到货后另做适配层 |
| `agent_guard.validate_result` 直接下标取值 | 改为防御式：缺键抛受控 ResultError | 原实现缺键抛 KeyError，与"程序异常不可伪装成功"冲突 |
| `pending / not_found / conflict / unavailable` 语义 | 保留并映射到退出码 5/6/11 等 | 与统一文档状态闭集保持一致，未新增状态值 |

## 10. 限制声明

- `committed` 仅表示本地 SQLite 事务已提交，**不是**服务端 MySQL 入库证明。
- 全部测试结果来自合成夹具与本机受控测试库，不代表千问/生产运行，也不等于平台能力已验证。
- 交付未经独立审核前只处于候选状态，不得宣称已上线。
