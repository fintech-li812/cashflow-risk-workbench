# 设计与接口说明（MEM-IMPORT-002 v1）

## 1. 目标与不做什么

目标：把制造业 xlsx 变成**可追溯、可复算、可核对**的 mfg-import.v1 导入包，每个规范字段都能定位到真实 Sheet/单元格与转换依据；字段被篡改时能从真实源查出来。

不做：现金流预测、财务评分、评级、现金折扣、行业扩展、数据库写入、平台/生产部署；不做主算法（另一队友负责）。

## 2. 模块划分

| 模块 | 职责 | 关键设计 |
|---|---|---|
| `canon.py` | 规范 JSON 与哈希 | 唯一序列化方式：`ensure_ascii=False, sort_keys=True, separators=(',',':'), allow_nan=False`；`source_revision` 与 `source_record_key` 的固定算法 |
| `xlsxraw.py` | 只读解析 xlsx XML | 直接读 `xl/worksheets/*.xml`，保留 XML 数值原文、公式与缓存、单元格是否存在；识别 1900/1904；支持 sharedStrings/inlineStr/str/b/e；**不执行宏、不解析外链、不 eval** |
| `convert.py` | 金额/日期转换 | Decimal；万元 ×10000 后 ROUND_HALF_UP 落分；拒绝 NaN/Infinity/非法字符串；1900/1904 序列、serial=60 虚构闰日、两位年份、非法日历日期一律报错不猜 |
| `scanner.py` | 扫描与出包 | 表头+别名匹配（缺列/重名列/别名歧义都报，不取第一项）；纵向表按字段名定位；重复保留；单位例外绑定源 SHA+Sheet+地址；输出 7 个文件 |
| `verifier.py` | 独立核对 | 结构/哈希/记录数 + **从真实源重导逐字节比对**，篡改定位到字段与源地址 |
| `report.py` | 离线 HTML | `html.escape` 全转义，无 `src=`、无外链、无脚本 |
| `selftest.py` | 自测 | 31 个正反例，独立预期来自冻结文件；任一 FAIL/意外异常→退出非 0 |

## 3. 字段与追溯结构

`records.jsonl` 每行：
```
source_record_key, record_type, source_file_sha256, sheet, row,
cells{地址: {type, raw, formula?, cached?, cache_status?}},
normalized{字段: {value, address, transform}},
issues[issue_id…]
```
- `cells` 保留该行全部存在单元格：区分**缺失单元格 / 空白元素 / 显式空串 / 空格 / 数值0 / 数字文本 / 公式有缓存 / 公式无缓存**
- `normalized.value` 为 元-2位小数字符串（金额）、ISO 日期（日期）或原文（文本）；无法可靠取值时为 `null` 并在 `transform` 写明状态
- `transform` 记录 `from_raw / from_unit / to_unit / factor / rounding / date_system / from_serial`

## 4. 单位与例外

- 映射声明列的**原单位**（样例现金流水等表头为万元）。转换：原精度 ×10000 → 元位 ROUND_HALF_UP 到分。
- `unit_exceptions.json` 的每条例外必须同时匹配 **源文件 SHA256 + Sheet + 单元格地址** 才生效；命中后规范值 `null`、原值保留、不乘 10000、不自动修正。示例绑定的是样例 `7e32b1ec…c13d0a3b` 的 `现金流水!D8`。
- 未批准单位保持待确认（`UNIT_UNKNOWN`），不套转换；没有通用阈值，不做"看着太大就纠正"。

## 5. 日期

| 情形 | 处理 |
|---|---|
| 数值序列（1900） | 按 1900 系统换算并记录 `date_system` |
| 数值序列（1904） | 按 1904 系统换算并记录 |
| serial=60（1900） | 报 `EXCEL1900_FICTITIOUS_LEAP_DAY`，值 null，**不冒充 1900-02-29** |
| 文本 `YYYY-MM-DD`（映射声明格式） | 校验为真日历日期 |
| `2026-13-05` / `2026-02-30` | 报 `INVALID_DATE`，值 null，不进位 |
| 两位年份 | 报 `TWO_DIGIT_YEAR`，不猜世纪 |

## 6. verify 的威胁边界（重要）

verify 除了核对包哈希，还用包内映射/例外快照**从真实源重新推导** records/issues/inventory 并逐字节比对。因此：
- 改字段 + 重算清单哈希 → 仍失败，并指出 `Sheet!行N 地址` 与真实值
- 源文件被替换 → `source_revision` 重算不符 → 失败

**不能证明的内容**：若真实源与全部可信哈希被同时替换，模块无法自证历史真相；源真实性要靠外部固定可信源摘要。本工具也不证明平台权限、数据完整性或版本已发布。

## 7. 确定性与稳定输出

- 输出排序：`(文件序, sheet, row, source_record_key)`；同源同映射重跑 `records.jsonl` 字节一致
- `manifest.json` 的 `created_at` 为唯一非确定字段，已在 `non_deterministic_fields` 明示，不参与字节比较
- 映射快照按**原始字节**写入包内，保证包内快照哈希 = 源映射哈希（否则 source_revision 无法复算）

## 8. 路径与输出安全

- `--output` 必须不存在（重名即拒绝，退出码 2）；符号链接输出拒绝
- 包内 `files[].path` 拒绝绝对路径、`..`、空段、重复；manifest 不含自身
- CSV 导出对 `= + - @ \t \r` 开头文本加 `'` 前缀，原文仍在 JSON 内保留
- HTML 全转义、离线；日志与输出不含路径/账户/私钥

## 9. 退出码

| 命令 | 0 | 1 | 2 |
|---|---|---|---|
| scan | 技术执行成功（业务疑点另报） | 运行期意外错误 | 参数/环境错误（目录重名、period 非法、身份字段缺失等） |
| verify | 全部核对通过 | 存在不符项或运行错误 | 参数错误 |
| selftest | 31 项全 PASS | 存在 FAIL/BLOCKED/意外异常 | 参数错误（工作目录已存在） |

程序异常不得伪装成 BLOCKED 或成功退出码；未执行项如实写"未执行/阻塞"。
