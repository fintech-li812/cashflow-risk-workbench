**已知事实**
1. **Q 的求和粒度**：v8 行 206 定义的是**逐笔样本**的因子 `B_ks`（每个观测值一个 0/1），但 v8 行 240—250 的实证表和演示看板（html 行 536—542、666—667）都是**按指标计数**（15 个指标各一个 0/1，看板 Q = 1 − 9/30 = 0.70）。两种数法得出的 Q 完全不是一回事，而 0.3 / 0.5 直接改灯。
2. **D 的归一化**：v8 行 334 写 `D = ΣvᵢXᵢ + ΣuᵣYᵣ`（原始财务比率加权和），而看板行 668—671 实现为 `D = Σw(2x̃ − 1)`（先归一化到 [0,1] 再映射到 [−1,1]），临界值 c=0。实测看板 D = −0.176。**两种写法下"D<0"的含义不同**：原始值加权和不可能天然以 0 为界。

**来源 / 缺口**
- v8 行 206、213、334 vs 看板行 536—549、666—671、790；两者未做过一致性裁决。

**可选方案**
| 方案 | 做法 | 影响 |
|---|---|---|
| A | 以**看板实现**为准（Q 按指标计数、D 用归一化写法），回写 v8 消除歧义 | 演示数字不用改；但 v8 正文要改两处 |
| B | 以 **v8 正文**为准，重做看板 | 学术表述更"正统"；但看板 Q=0.70 / D=−0.176 全部作废重算，阈值也要重标 |
| C | 两个都保留但分别命名（Q_指标 / Q_样本，D_norm / D_raw） | 不丢信息；但复杂度翻倍，演示时说不清 |

**推荐及理由**：**A**。理由：看板是目前唯一"真的算出了数"的实现（Q=0.70、D=−0.176 可在页面上核对），而 v8 正文是文字表述。把 v8 正文改成与实现一致，比把实现推翻重算成本低得多。**但必须同时确认 0.3/0.5 这两个阈值是按哪种 Q 标定的**——如果阈值原本是按"逐笔样本"定的，改用"按指标计数"后阈值就失效了。

**请确认一句话**：Q 是**按 15 个指标各算一个因子**（看板现在的做法，得 Q=0.70），还是**按每笔数据各算一个因子**？D 是用**归一化后的加权和**（看板做法，得 −0.176），还是**原始比率的加权和**？（另外：0.3 和 0.5 这两个门槛是按哪种 Q 定的？）

## P-12 · 客户分几次付款（部分到账），算"到账不符"还是"正常分次回款"？

**已知事实**
- 四行业共约 **28 处**到账 ≠ 应收（制造 4、零售 4、建筑 15、科技 5），比例 59%~98%，含科技行 8 的 135%（超收）。
- 建筑 `AR20261005` 有两笔到账：14% 与 85%（合计 99%），疑似分次回款，但现规则是**单笔严格相等**，会判"金额不符"。
- 数据闸公式实现_v2 行 212 的未决点明确："多笔分次到账、同号多条应收、找不到单据和金额精度容差**没有定义**"。
- 包B A08 行 347 也写明："6 是否作为部分回款另行入账属于扩展规则，须确认后另测"。

**影响**
- 若属分次回款却按"金额不符"处理：有效缓冲（F-04）少计、回款缺口（F-20）多算 → 缓冲偏低 → 误报黄/红。
- 若属真实差异却按"分次回款"放行：等于**用部分到账自证全额验证**，违反协议 §5.7。

**可选方案**
| 方案 | 做法 | 影响 |
|---|---|---|
| A | 维持单笔严格相等（现状），28 处全部标"金额不符" | 保守；但会误伤分次回款，且演示时"到处都是不符"很难看 |
| B | 新增"按单据号合并"口径：同单据多笔到账合计 ≥ 应收才计已验证，单笔不比较 | 符合业务；需要新规则 + 新用例，且要区分"分次"与"少付" |
| C | 维持严格相等，但把"部分到账"单列为一种状态（不计入有效缓冲、也不算异常） | 折中；需要新增状态枚举 |

**推荐及理由**：**C 过渡、B 为目标**。理由：B 是业务上正确的做法但需要新增规则与测试（包B 已明确不在本轮 45 条内）；C 能在不动现有规则的前提下避免"把分次回款当异常"，代价是要新增一个状态词——而这会牵动数据闸输出闭集，需要批准。

**请确认一句话**：建筑 `AR20261005` 的"14% + 85%"这两笔，是**同一笔应收的分次回款**（那就按单据合并计算），还是**两笔独立的差异**（那就都算金额不符）？

## P-14 · 授信里的"已使用"和"未使用"怎么分开？
