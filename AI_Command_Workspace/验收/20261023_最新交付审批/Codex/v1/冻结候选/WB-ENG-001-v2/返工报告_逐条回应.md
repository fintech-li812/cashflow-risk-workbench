## 一、必改项 R-01 / R-02 / R-04

### R-01（已修）pending 无实际值的假绿路径

**审核问题**：`log_feedback` 无条件必填 `predicted_value` + `actual_value`，且不接受 null，导致"实际值尚未产生"时只能填 0 或假数，污染准确率分母。

**采用方案**：审核给出的方向 ①（移除无条件必填 + 类型可空 + 服务端按 `accuracy_label` 校验）。

**改动**：

| 文件 | 改动 |
|---|---|
| `工具定义_v1.1.json` | `required` 中移除 `predicted_value`、`actual_value`（12 项 → 10 项）；两字段 `type` 改为 `["string","null"]`；新增 `allOf`：当 `accuracy_label ∈ {accurate, inaccurate}` 时 `required: [predicted_value, actual_value]` |
| `对接协议_v1.1.md` §5.3 | 新增 R-01 修订段：三态语义、禁止 0 代填、Schema 只做静态约束、观察窗口由服务端校验 |
| `validate_contract.py` A 节 | A12 改为"10 项无条件必填"；新增 `predicted_value`/`actual_value` 可空断言 |

**关于 Codex 处置意见的遵守**：Codex 明确要求"**不要额外发明『所有 pending 一律不允许已有 actual 值』的限制**"。因此我**没有**加"pending 必须无 actual_value"的 Schema 约束，并专门增加一条用例固化该口径（见下）。

**新增用例（B 节，全部 PASS）**：

- `R-01 正例: pending 省略两金额（不得被迫填 0）` → 合法 ✅
- `R-01 正例: pending 显式 null 两金额` → 合法 ✅
- `R-01 说明: pending 携带 actual_value 也允许（按 Codex 处置不增设禁止）` → 合法 ✅
- `R-01 反例: accurate 缺 actual_value` → 拒绝（`actual_value is a required property`）✅
- `R-01 反例: inaccurate 缺 actual_value` → 拒绝 ✅
- `R-01 反例: actual_value 非金额格式`（`"abc"`）→ 拒绝 ✅

**复验条件达成**：pending 无实际值可提交；accurate/inaccurate 缺实际值被拒。
**仍未做**：真实 MySQL 插入 NULL 成功——需环境（BLOCKED，见 D 节）。

### R-04（已修）v_template_published_latest 未排除被替代版本

**审核问题**：该视图是唯一没有 `NOT EXISTS` 的纠错类视图；旧行仍为 published 会参与 `MAX(effective_from)`，且并列时返回多行 → `load_param_template` 可能取到被替代参数。

**改动**（`init_v1.1.sql` [7]）：

1. 加 `AND NOT EXISTS (SELECT 1 FROM param_template s WHERE s.supersedes_id = p.id AND s.tenant_id = p.tenant_id)` —— 与其余 6 个纠错视图同口径；
2. 并列确定性：由 `effective_from = (SELECT MAX(...))` 改为 `p.id = (SELECT p3.id ... ORDER BY p3.effective_from DESC, p3.id DESC LIMIT 1)`，保证每租户每行业**最多 1 行**；
3. 显式加 `p.effective_from <= UTC_TIMESTAMP(6)`（原写法只在子查询里过滤，主行未过滤）。

**脚本新增断言**（C7c，PASS）：同时校验 `NOT EXISTS=True`、`同租户=True`、`并列确定性=True`（要求 ORDER BY...DESC + LIMIT 1 同时存在）。

**为什么 v1 测试没发现**：v1 的 C17 只检查"已含 NOT EXISTS 的视图"是否有 tenant 限定，天然覆盖不到一个**没有** NOT EXISTS 的视图——这一点审核说得对，已在注释中写明。

**仍未做**：真实库构造"旧行被替代 + 同 effective_from"两例验证返回 1 行——需 MySQL 环境（BLOCKED）。
