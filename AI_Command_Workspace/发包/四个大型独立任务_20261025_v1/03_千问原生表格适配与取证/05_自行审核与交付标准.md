# 自行审核与验收规则

开发完成后换成审核角色，按本包每条验收点找反例。不能只通读代码或交一张全通过截图。
每个必测case_id有真实输入、独立冻结expected、实际值、退出码、至少一份原始证据及SHA256。自测不修改预期，故意断言失败必须真实返回非0。
程序必须实现src/selftest.py --workdir <全新目录> --report <报告JSON>。顶层报告有total/passed/failed/blocked/not_run/tests，数量闭合，tests每项有case_id/status/expected/actual/evidence。
evidence是列表，每项{path,sha256}，path相对--workdir，文件必须真实存在且摘要一致。成功测试status=passed；失败/未执行/阻塞不能塞进passed。测试“正确阻断缺能力”可以通过，但平台本身依旧未验收，二者分开登记。

执行冻结验收：
python -B 自验入口.py --submission <你的交付目录> --output-dir <全新验收目录>

它会校验整个任务包原件、调用你的selftest、核对必测ID和逐条证据，并独立构造反例跑黑盒CLI。01/02还会执行上一版冻结基线验收，不能跳过或改旧入口。
admission.json工程准入为passed且directly_submittable=true才可交候选。输出不全、缺依赖、缺case、证据不存在或黑盒不符，返回2且不准入；不得改验收脚本来适配实现。
冻结工具不会证明真实平台、数据来源真实性或生产部署。03/04允许工程准入通过同时platform_acceptance=blocked，必须在回执中醒目标明，不得写“全链已验收”。

交付根目录必须含README.md、requirements.lock.txt、实现与需求映射.json、未实现与限制.md、交付回执.json、src/、tests/、fixtures/、expected/、test-output/、manifest.json、SHA256SUMS.txt。
manifest枚举每个实际工件，包括嵌套manifest；仅排除根manifest和根SHA256SUMS，避免循环。SHA256SUMS覆盖除自身外全部工件。ZIP不要含.venv、缓存、私钥或真实业务敏感流水。
另交自审报告.md：发现过什么、修了什么、剩什么、命令与退出码、必测覆盖、原件前后摘要、新目录ZIP解包复现、缺项负责人。

本轮用户要求执行者自行审核；通过冻结工程验收即可新增交付自己的候选版本，不增加必须等待Codex/DeepSeek手审的门槛；X仍统一检查最终成果。
此条仅适用于本批四包，不能据此批准覆盖原件、修改正式服务或生产上线。历史其他代码候选独审流程不自动取消。
