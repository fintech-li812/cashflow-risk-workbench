# 本轮接入矩阵

统一入口为千问办公Agent与同一MCP连接器。整合代码为独立候选，不覆盖已冻结v2和原工作台空文件。

| 组件 | 已接入的实际能力 | 边界 |
|---|---|---|
| 项目状态 | get_workbench_status返回当前结果配置、源文件与真实数据库连接状态 | 不把函数被调用当成平台原生重算证据 |
| 制造业源目录 | list_manufacturing_sources列唯一注册样例及SHA | 不打开其他行业或任意用户路径 |
| 单元格取证 | inspect_manufacturing_source只读企业基本信息A1:C10、现金流水A1:I15，枚举8个Sheet | 原始XML值/公式/缓存分别保留，不执行、不改表 |
| 就绪检查 | get_manufacturing_readiness明确单位疑点、重复和缺少绑定 | 不执行gate词表、不把部分到账视作错误 |
| 结果守卫与解释 | 复用v2真实使用的agent_guard和批准快照 | 当前财务快照是合成演示，不能冒充本地样例的计算结果 |
| MySQL存取 | 原read/save/query工具原名原参数，复用已跑通的真实存取服务 | 当前为授权隔离库，不是正式生产服务 |
| 辅助看板 | /api/workbench和/api/source-inspection接实际只读状态 | 本地网页不能替代千问平台验收 |
| 统一Agent技能 | mfg-workbench-integrated按状态→来源→取证→就绪诊断路由，演示留档独立分支 | 待千问实际装载/调用实测，不凭文件存在声称完成 |
| 外包报告导出 | MEM-REPORT-002任务包已发，接口/自验/端口已固定 | 实现未回件，不加载不存在模块 |
| 外包完整导入器 | MEM-IMPORT-002 v2任务书承接222 | 当前只读探针不是完整导入器，不代签交付 |
| 原生千问工作簿及公式重算 | 工作目录未发现已登记的平台工作簿标识；用户函数可用确认保留 | 固定xlsx值不是原生公式执行证据，不能伪称就绪 |
| 核心滚动/高级三态 | 第二阶段方案库保留 | 本轮后置，不自动恢复评级/折扣/多行业 |

本机HTTP辅助预览沿用127.0.0.1:18765，MCP原生接入使用stdio，不新增监听端口。13317仅是已有授权隔离数据库隧道。两外包包均CLI，无需端口或服务器凭据。
