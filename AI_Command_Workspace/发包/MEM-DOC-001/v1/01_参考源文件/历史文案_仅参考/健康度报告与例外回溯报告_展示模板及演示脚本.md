# 两份报告展示模板 + 演示脚本 + 页数预估

> 载体：科技服务业样板企业「智汇云创软件技术（深圳）有限公司」（M=65.1 万元，K黄=1、K红=0.5）。
> 文中数值均为**演示示例**，正式汇报以工作台系统实际计算结果为准。
> 两份报告分别对应方案中的「月度偿债安全健康度报告」（每月 1 号推送管理层）与「季度例外审批回溯报告」（每季度 1 号推送）。

---

## 一、页数预估总览

| 报告 | 建议页数 | 结构 |
|---|---|---|
| A. 月度偿债安全健康度报告 | **8 页** | 封面 1 + 结论 1 + 现状 1 + 方法 1 + 情景 1 + 聚焦 1 + 建议 1 + 闭环 1 |
| B. 季度例外审批回溯报告 | **6 页** | 封面 1 + 概览 1 + 部门例外率 1 + 异常识别 1 + 审计行动 1 + 闭环改进 1 |

> 均为"汇报级"精简页数；若用于答辩演示可再拆出 1 页"系统架构/数据链路"作附录，各自 +1 页。

---

## 二、模板 A · 月度偿债安全健康度报告（8 页）

### 第 1 页｜封面

- **内容**：报告名「2026-09 偿债安全健康度报告」；企业名与行业；右上角放**综合风险等级大灯（🟡 黄灯）**；底部标注"数据区间 2025-10~2026-09｜AI 自动生成｜2026-10-01"。
- **演示口播**：
```
各位管理层好，这是本月自动生成的偿债安全健康度报告。总体风险等级为黄灯——
短期可控，但有一个需要立即关注的信号：联合冲击情景下缓冲会转负，本报告会重点讲这个。
```

### 第 2 页｜本期核心结论（一页看懂）

- **内容**：三缓冲状态三张迷你仪表（现金缓冲 🟡 42.3 万、时间缓冲 🟡 18 天、融资缓冲 🟢 可用 1200 万）；一句话结论条："现金与时间缓冲双黄灯，主因政务云 461 万应收逾期；联合冲击下缓冲 -5.6 天，需 10 月内落地两项动作"。
- **演示口播**：
```
一句话结论：现在现金和时间缓冲都进了黄灯区，主因是政务云那笔 461 万的逾期；
按最坏情景测算缓冲会转负，所以这个月内必须落地两个动作，后面第 6、7 页会讲。
```

### 第 3 页｜当前财务状况

- **内容**：三缓冲与阈值对比表——现金缓冲 42.30 万（黄灯线 65.10 / 红灯线 32.55，距红灯 +9.75）；时间缓冲 18 天（黄灯 20 / 红灯 10）；融资缓冲可用 1200 万、已用 68%。附期末现金余额近 12 个月折线。
- **演示口播**：
```
现金缓冲 42.3 万，在黄灯线上方、红线下方，距红线还有 9.75 万的安全垫；
时间缓冲 18 天，贴着黄灯线；融资缓冲还健康，可用授信 1200 万、用了不到七成。
说明问题主要在经营性回款，不在融资端。
```

### 第 4 页｜压力测试方法与情景设定

- **内容**：四类冲击说明（回款冲击：Top3 客户延付 30 天；融资冲击：授信收紧 30%；成本冲击：人力成本 +15%；联合冲击：三者叠加）；每类冲击对 M 基数的敏感度小表。
- **演示口播**：
```
我们把压力测试固化为四类情景：回款、融资、成本，以及三者叠加的联合冲击。
这不是假设恐惧，而是每月 1 号自动跑一遍，逼着我们在最好情况下看到最坏结果。
```

### 第 5 页｜四情景最坏结果对比

- **内容**：柱状/对比表——各情景最坏现金缓冲、剩余天数、风险等级：
回款冲击 31.2 天 🔴｜融资冲击 42.5 天 🟡｜成本冲击 38.0 天 🟡｜联合冲击 **-5.6 天 🔴**。
- **演示口播**：
```
单独看，融资和成本冲击都还能扛，回款冲击已经触红；但真正的红线是联合冲击——
剩余 -5.6 天，意味着如果三件事同时发生，我们会在一周内断现金流。这是本月最重要的发现。
```

### 第 6 页｜风险聚焦（联合冲击专题）

- **内容**：联合冲击归因拆解——贡献度条形（应收延付 52%、授信收紧 28%、成本上升 20%）；三项缓冲突围动作卡片（催收政务云尾款、启用中行抵押授信、暂缓非关键采购）。
- **演示口播**：
```
联合冲击里，回款延付贡献了一半以上。所以优先级很清楚：先催政务云尾款、
再备好中行的抵押授信作为备胎、同时暂缓非关键采购。三张卡片都对应到责任人和时间点。
```

### 第 7 页｜应对建议（短/中/长期分层）

- **内容**：三层建议——短期（10 月内）：催收尾款 112 万、恢复现金缓冲至黄灯线以上；中期（Q4）：将单一大客户应收占比降至 40% 以下、申请授信扩容；长期：建立客户信用分级与预付款机制。
- **演示口播**：
```
短期这个月只做一件事：把缓冲拉回黄灯线以上；中期四季度解决客户集中的结构性问题；
长期用信用分级和预付款从根上降低回款风险。每一层都能量化验证。
```

### 第 8 页｜闭环与后续

- **内容**：闭环验证矩阵片段——决议事项、责任人、截止时间、验收标准（缓冲≥黄灯线）；"下次验证：2026-11-01 月度报告复核"；相关钉钉预警记录编号。
- **演示口播**：
```
最后是闭环：两项动作的责任人和时间点都锁定到人，验收标准是缓冲回到黄灯线以上。
下月 1 号的报告会自动复核这两项是否兑现——系统不是发完预警就结束，而是要看到结果。
```

## 三、模板 B · 季度例外审批回溯报告（6 页）

### 第 1 页｜封面

- **内容**：报告名「2026 Q3 例外审批回溯报告」；企业名；右上角放**例外健康度提示**（⚠️ 1 个部门例外率超阈值）；底部"季度回溯｜AI 自动生成｜2026-10-01 06:00"。
- **演示口播**：
```
这是三季度的例外审批回溯。本季度有一个部门例外率越过了阈值，已经自动触发审计检查，
这页先给结论，后面展开。
```

### 第 2 页｜本期概览

- **内容**：四个 KPI 卡——例外放行 23 次、合计 486.5 万元、占单笔支出 8.3%、环比 +2.1pct；近四季度例外率趋势折线（缓慢上升，标注本季）。
- **演示口播**：
```
三季度例外放行 23 笔、合计 486.5 万，占单笔支出 8.3%，比上季度还升了两个点。
趋势在往上走，这是需要警惕的信号。
```

### 第 3 页｜各部门例外率

- **内容**：横向条形图 + 20% 阈值红线——研发部 **28% 🔴**、市场部 12%、交付部 9%、行政部 6%；右侧标注研发部缺口 +8pct。
- **演示口播**：
```
分部门看，研发部 28% 明显越过 20% 阈值，其他部门都在正常区间。
研发部的例外不是零星发生，而是系统性偏高，值得深挖。
```

### 第 4 页｜异常识别

- **内容**：三类异常规则命中清单——① 研发部例外率 28% 超阈值；② 理由"客户临时加急"重复出现 6 次；③ 采购部单笔例外金额超季度预算 15%。每条配"风险解读"。
- **演示口播**：
```
三类异常规则命中了两类半：研发部超线、'客户临时加急'这个理由重复了 6 次，
还有一笔采购超了季度预算 15%。理由高度重复，往往说明这个'例外'其实已经常态化，是最需要警惕的。
```

### 第 5 页｜审计行动

- **内容**：已自动创建的审计检查任务卡——检查对象：研发部例外流程；触发规则；责任人：内控专员；截止时间：2026-10-15；同步通知内控/审计部门的钉钉记录编号。
- **演示口播**：
```
系统没有只停留在'报出来'，而是自动给研发部创建了审计检查任务、指定了内控专员、
并通知了审计部门，10 月 15 日前要给出检查结论。这就是闭环的第一步。
```

### 第 6 页｜闭环与改进

- **内容**：改进建议（例外白名单固化、审批权限微调、例外理由结构化选项）；下季度跟踪指标（研发部例外率目标 ≤20%）；"下次验证：2027-01-01 季度报告"。
- **演示口播**：
```
改进方向有三：把合理的'临时加急'固化成白名单而不是反复走例外、微调研发部审批权限、
把例外理由改成结构化选项避免随手填。下季度我们会盯研发部例外率是否回落到 20% 以下。
```

## 四、页数预估汇总

| 报告 | 页数 | 用途建议 |
|---|---|---|
| 月度偿债安全健康度报告 | 8 页 | 每月 1 号管理层汇报 / 答辩"常态化压力测试"演示 |
| 季度例外审批回溯报告 | 6 页 | 每季度 1 号合规汇报 / 答辩"审批-例外-审计闭环"演示 |

- **答辩合计 14 页**（约 12–15 分钟讲完，每页 1 分钟口播）。
- 若两报告合并为一场"月度 + 季度"联合汇报，可去重封面，压到 **12 页**。
- 建议附录各加 1 页"数据链路/系统架构"，用于展示工作台如何自动生成报告，答辩更有说服力（合计 16 页）。

> 说明：两份模板的每页口播稿已按"结论先行、数据支撑、动作闭环"的汇报逻辑撰写；数值为演示示例，接入真实样例数据后可一键替换。
