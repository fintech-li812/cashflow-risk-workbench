# 八条制造业现金流追问（v3）

继承 CX-AGENT-002 的 v2 原文（同目录“_v2_继承原文.md”）。占位符必须来自实际数据或工具返回，没有就写未知。

1. 缺输入：“这次缺少【期间/字段】，暂时不能给出完整余额。请提供该值或可核对的来源；缺失不能当0。”
2. 单位疑点：“【来源/单元格】原值为【值】，声明单位为【单位】。请确认实际单位；确认前不自动放大或缩小。”
3. 重复疑点：“【记录A/B】可能重复，证据是【交易标识/来源】。请核实是否为同一笔；我不会仅凭金额相同删除记录。”
4. 分次回款：“这张应收【金额】已分次收到【实际到账】，剩余【差额】。请确认未收部分的计划日期；部分到账不自动算数据错误。”
5. 余额差异：“计算期末【值】、独立实际期末【值】，差异【值】。请先核对统计账户范围、截止时间及遗漏/重复记录。”
6. 数据范围：“目前只有【经营部分】，尚缺【其他分类/期初/实际余额】。要补齐全口径，需提供这些数据；现结果只代表经营部分，不能代表完整企业现金流。”
7. 保存待确认：“刚才调用未取得确定保存结果，状态为未确认。请保留请求标识【request_id】，先按实际回查能力核实，不另建一笔重复提交。”
8. 结果确认：“本次已读取【来源与版本】，完成【步骤】；【步骤】仍未完成。请核对【具体金额/缺项】，确认后再进行下一步。”

## v3 相对 v2 的变化

| 条 | 变化 | 原因 |
|---|---|---|
| 6 | “现结果不能代表完整企业现金流”改为“现结果只代表经营部分，不能代表完整企业现金流” | 统一接口要求：部分口径有单独视图与说明，不能静默混同 |
| 7 | “刚才调用未取得确定保存结果”后补“状态为未确认”；占位符由【标识】改为【request_id】 | 明确超时是不确定态而非失败，且回查键必须是同一 request_id |
| — | 新增使用约束 | 保存超时沿用同一 request_id 回查，禁止换 ID；同键不同载荷报冲突不覆盖 |
| — | 未改动其余七条 | v2 口径继续有效 |
